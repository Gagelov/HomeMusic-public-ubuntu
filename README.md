# HomeMusic на Яндекс Станции Лайт

Мост «Алиса → HomeMusic» для рутованной Станции Лайт 1. Музыка **не кешируется**:
станция сама тянет поток Navidrome своим штатным плеером (GStreamer), а мост лишь
отдаёт ей директиву `audio_play` по локальной шине Quasar. Ни `ffmpeg`, ни
`aplay`, ни захвата ALSA нет — `maind --mediad` остаётся жив.

## Как это работает

Локальная шина `127.0.0.1:9875` принимает protobuf-кадры Quasar:

- `253 = 211` — обычная директива (`quasar.proto.Directive`). Мы отправляем
  `audio_play` с URL потока Navidrome, названием и позицией. Дальше играет
  штатный плеер станции: он же показывает трек, принимает громкость и паузу.
- `253 = 210` — remoting-запрос. Через `AliceCapability` отправляем
  `cancelDialog`, чтобы Алиса не успела сказать «такой песни не найдено»,
  пока мы получаем очередь с сервера.

Очередь и позиция хранятся в `/data/opt/homemusic`, на флешку не пишется ни
один трек. Когда трек доигрывает, сторож `hm-play.sh` отправляет следующую
директиву с тем же потоком.

Пока HomeMusic играет, `music-block.sh` временно переводит домены Яндекс Музыки
(`music.yandex.net/ru/com`, `strm.yandex.net`) в NXDOMAIN через штатный
`unbound`. Это не даёт облаку Алисы перебить наш поток своим треком и убирает
попытки сопряжения с сервисом музыки. Голос Алисы, uniproxy и остальной
`yandex.net` не блокируются; после остановки HomeMusic конфиг возвращается.

## Что умеет

Фразы с явной привязкой к серверу:

- «Алиса, включи музыку через сервер» — случайные треки библиотеки;
- «Алиса, включи любимые через сервер» — ♥ из Navidrome/HomeMusic;
- «Алиса, включи плейлист <название> через сервер»;
- «Алиса, включи <исполнителя/трек> через сервер» — поиск;
- «Алиса, включи <трек> с нашего сервера» / «из HomeMusic».

Пока играет HomeMusic:

- «следующий», «дальше», «переключи»;
- «предыдущий», «назад», «верни»;
- «пауза», «продолжи», «стоп», «выключи»;
- «лайк», «нравится», «дизлайк», «не нравится»;
- «перемотай на 30 секунд», «назад на минуту»;
- «что сейчас играет» / «что за песня» — отвечает сама станция, без Shazam;
- громкость — **штатная**, её обрабатывает сама станция.

Короткие команды без «Алиса» («дальше», «пауза», «лайк», «тише») берутся из
`maind.log` командным споттером: пока играет штатный плеер, он включён.

Обычные фразы без «через сервер» не перехватываются: Яндекс Музыка, Алиса,
таймеры, умный дом и громкость работают как раньше. Если во время HomeMusic
попросить обычную музыку у Алисы, мост завершает свою сессию и возвращает звук
Яндексу.

## Установка на колонку

Нужны root, SSH на порту 2222 и Entware (`yse bootstrap`). На колонке:

```sh
/opt/bin/opkg install jq socat curl
mkdir -p /data/opt/homemusic
# скопировать сюда: hm-native.sh hm-play.sh voice-bridge.sh command-watch.sh
#                   mediad-guard.sh music-block.sh hm-api.sh hm-api-daemon.sh
#                   alice-text.sh alice-text.awk
chmod 755 /data/opt/homemusic/*.sh
# config: SERVER=... USER=... PASSWORD=...
chmod 600 /data/opt/homemusic/config
```

Init-скрипт `S99zhomemusic` положить в `/etc/init.d/` (rootfs временно
перемонтировать в rw, затем обратно в ro) и выполнить:

```sh
/etc/init.d/S99zhomemusic start
```

Проверка:

```sh
/data/opt/homemusic/hm-play.sh status
tail -f /data/opt/homemusic/voice.log
/data/opt/homemusic/voice-bridge.sh --test 'Алиса, включи любимые через сервер'
```

`mediad-guard.sh` держит ровно один `maind --mediad`; он не останавливает его
во время игры, потому что штатный плеер живёт именно там. После перезагрузки
`S99zhomemusic` сбрасывает старые lock-файлы и состояние плеера.

Остановка/откат:

```sh
/etc/init.d/S99zhomemusic stop
# удалить /etc/init.d/S99zhomemusic и /data/opt/homemusic
```

## API для приложения

`hm-api.sh` под `socat TCP-LISTEN:8099` даёт Хабу управлять колонкой:

- `GET /status` — что играет, позиция, очередь;
- `POST /command` с `{"action":"next"|"prev"|"pause"|"resume"|"stop"}`;
- `POST /play` с `{"index":0,"position":0,"tracks":[{"id","artist","title","duration"}]}`
  — очередь из приложения.

Все запросы требуют заголовок `X-HM-Token`, равный `API_TOKEN` из `config`
(файл `600`). В приложении адрес и токен задаются в **Меню → Яндекс Станция**;
они хранятся в браузере и уходят на Хаб. Серверные `STATION_URL` и
`STATION_TOKEN` — необязательный запасной вариант. Порт слушает LAN; токен не
даёт управлять колонкой без него.

## Источник

`hm-play.sh` ходит в Subsonic API Navidrome (`/rest/...`) с администратором из
`config`; поток запрашивается как `format=mp3&maxBitRate=192` и отдаётся
штатному плееру станции по HTTPS. Для «любимых» используется `getStarred2`;
для поиска — `search3`; для плейлистов — `getPlaylists`/`getPlaylist`.

`SERVER` — адрес Navidrome по HTTPS, например `https://192.168.50.107:4533`.
Для него на станцию нужно поставить локальный CA HomeMusic.
